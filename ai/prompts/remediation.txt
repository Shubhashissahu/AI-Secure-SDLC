## Your task

Produce a secure replacement for the vulnerable code, plus a short explanation a developer can act on immediately without needing to look anything up.

Rules:
- The patch must be a minimal, targeted fix — do not rewrite unrelated code or restructure the surrounding function beyond what's needed to close the vulnerability.
- The patch must actually compile/run in context — use the same variable names, imports, and style already present in the surrounding code.
- The explanation should say what was wrong and why the fix closes it, in plain language, in 2-4 sentences.
- For hardcoded secrets (CWE-798): Move secret to environment variables (`process.env` or `System.getenv`).
- For SQL injection (CWE-89): Use parameterized queries (`PreparedStatement` in Java, binding arrays in JS/TS).
- For Command Injection (CWE-78): Avoid shell invocation; use `execFile` with array arguments or strict allowlists.
- For Path Traversal (CWE-22): Canonicalize paths using `path.resolve` / `path.basename` and enforce root directory bounds.
- For Insecure Deserialization (CWE-502): Replace unsafe deserializers with standard `JSON.parse()`.
- For SSRF (CWE-918): Validate URLs against an authorized domain allowlist and block private IP ranges.
- For Weak Cryptography / Hashing (CWE-327, CWE-916): Use `AES-256-GCM` for encryption and `bcrypt`/`argon2` for password hashing.
- For Open Redirect (CWE-601): Verify redirect target URLs are relative or match allowed hostnames.
- For Insecure File Upload (CWE-434): Sanitize filenames, generate random UUIDs, and whitelist file extensions.
- For XXE (CWE-611): Disable external entity resolution (e.g. `noent: false`, `disallow-doctype-decl`).
- For LDAP Injection (CWE-90): Escape LDAP filter metacharacters (`\`, `*`, `(`, `)`, `\0`).
- For NoSQL Injection (CWE-943): Use `mongo-sanitize` and enforce strict scalar types on query parameters.
- For Prototype Pollution (CWE-1321): Guard against `__proto__`, `constructor`, and `prototype` in merge/clone utilities.
- For ReDoS (CWE-1333): Use linear non-backtracking regex patterns without nested quantifiers.

## Output format — CRITICAL

Respond with ONLY a single JSON object. No markdown code fences, no preamble. Exactly this shape:

{
  "patch": "string — the corrected code",
  "explanation": "string — 2-4 sentences"
